# Learning guide

Work on one roadmap task at a time. Read its objective and acceptance criteria, then try to design and implement it yourself. Ask Codex for a hint when stuck; request pseudocode or code only if the earlier level of help is insufficient.

For each task:

1. State the behavior in your own words and choose a small interface.
2. Write the smallest implementation that can demonstrate the behavior.
3. Add focused tests for normal and boundary cases. Run the checks in the README.
4. Ask for a review. Discuss mistakes before changing the design.
5. Update `progress.md` with the result and the next step. Codex should maintain this with you after meaningful progress.

A task is complete when its behavior exists, its relevant tests pass, and its important design choices are recorded. Passing checks on an empty package does not complete an exercise.

The roadmap is a guide, not a deadline. If one task is too large, split it. If a concept is unclear, pause for a tiny experiment related to that task. Keep a runnable path through the project whenever possible.
